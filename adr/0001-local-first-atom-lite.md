# ADR 0001: ATOM LiteとローカルHTTP APIを採用する

## ステータス

提案中

## 背景

目的は、自宅LAN内から家電を赤外線操作することです。最初からクラウド、MQTT、Home Assistant、スマートフォンアプリまで導入すると、赤外線送信そのものの検証が遅くなります。

候補のM5Stack ATOM Lite（C008）は、Wi-Fiと赤外線送信機を小型筐体に内蔵しています。送信PoCのために別途赤外線LEDの駆動回路を作らなくてよい点を評価します。

## 決定

- デバイスはM5Stack ATOM Lite（C008）を第一候補とする
- 初期通信はATOM Lite上の小さなHTTP APIとする
- 操作端末側には標準ライブラリのみのGo CLIを置く
- 実行時は自宅LAN内に限定する
- 赤外線学習が必要になった時点で、38kHz受信モジュールを追加する

## 捨てるものと許容する理由

### HTTP APIを採用することの欠点

- LAN内APIの認証、再送、状態管理を自分で設計する必要がある
- Wi-FiのIPアドレス変更に対処する必要がある
- エアコンの状態同期をHTTPだけでは解決できない

初期用途は単一端末・単一LAN・少数コマンドなので、これらはログ、タイムアウト、allowlist、DHCP予約で段階的に扱えると判断します。

### MQTTやHome Assistantを採用しないことの欠点

- 既存のスマートホーム連携をすぐには利用できない
- 複数デバイス管理やイベント連携は後から追加する必要がある

一方で、初期PoCにブローカーや別サーバーを増やさず、故障箇所をATOM LiteとCLIに限定できます。必要性が確認できた後にアダプターとして追加します。

### ATOM Liteを採用することの欠点

- GPIO数や処理能力は大規模な制御盤には向かない
- 赤外線受信機能は別部品が必要
- 非公式販売元から購入すると、付属品や保証の確認が必要

テレビや少数の家電を操作する最初の段階では許容します。規模が増えた場合は別のESP32基板や専用ゲートウェイを再評価します。

## 代替案

- ESP32 DevKitC + 外付け赤外線LED回路: 安価で自由度が高いが、配線と駆動回路の検証が増える
- Home Assistant + IRブリッジ: 拡張性は高いが、初期PoCに対して構成が大きい
- 市販スマートリモコン: 早く使えるが、Go CLIや信号処理を自作する目的に合わない

## 見直し条件

- 対象機器が3台を超える
- 外出先操作が必要になる
- 家電状態の同期や自動化が中心になる
- ATOM LiteのHTTP APIだけでは信頼性を確保できない
